# Локальные подключения соцсетей

В LABRICA: **Настройки → Социальные сети → Подключить**. Введите доступы, нажмите «Проверить и подключить». Сервер проверит аккаунт по API, а затем сохранит подключение. Действие «Проверить доступ» только читает сведения; публикаций оно не создаёт.

| Площадка | Подключение | Отправка в этой версии |
|---|---|---|
| Telegram | Токен BotFather + @канал или ID; бот — администратор канала с правом публикации | Текст, фото, MP4. Файл отправляется напрямую с компьютера через сервер |
| VK | Токен пользователя с `wall`, `photos`, `groups`; администратор/редактор сообщества | Текст и изображения на стене сообщества. Видео пока не поддерживается |
| Instagram | Instagram Login access token, ID профессионального аккаунта; `instagram_business_basic`, `instagram_business_content_publish` | Изображение или Reels по публичной HTTPS-ссылке, подпись. Текст без медиа не отправляется |
| Threads | Threads access token; `threads_basic`, `threads_content_publish` | Текст; изображение/видео по публичной HTTPS-ссылке |
| YouTube | OAuth access token, `youtube.upload` + `youtube.readonly`. Для автоматического обновления: Client ID, Client secret и refresh token | Загрузка видео, название, описание и выбранная видимость; по умолчанию приватное |
| МАКС | Токен бота из MAX для бизнеса + числовой `chat_id`; бот — администратор с правом публикации | Текст, JPEG/PNG, MP4/WebM. Прямая загрузка файла через сервер |
| TikTok | OAuth access token с `user.info.basic`, `video.publish`. Для обновления: Client key, Client secret, refresh token | MP4/WebM до 50 МБ; параметры аккаунта, явное согласие, затем Direct Post и проверка статуса |
| Дзен | Ручной перенос через студию | Прямой API-постинг в этой версии не реализован |

Для аккаунтов сторонних пользователей Meta может потребовать проверку приложения; для своих тестовых аккаунтов настройте соответствующие роли приложения. Не используйте Facebook Login token вместо Instagram Login token. Пока полного перенаправления OAuth из приложения нет: в форме вставляется токен, полученный официальным способом. У каждого токена есть собственный срок и права; при истечении используйте «Заменить ключи». YouTube и TikTok поддерживают обновление по refresh token; остальные площадки требуют нового токена вручную.

Локальный сервер не публикует файлы в интернете. Поэтому Instagram и Threads требуют URL файла на вашем публичном сайте/хранилище. Адреса localhost, локальной сети и data URL для этих двух площадок отклоняются. Требования к формату/размеру проверяет также сама площадка. Для Telegram подпись к медиа ограничена 1024 символами, сообщение — 4096; фотографии — до 10 МБ. Общий лимит загрузки здесь — 50 МБ. Карусели и массовая загрузка файлов пока не реализованы.

## Как проверить настоящую отправку

1. Подключите свой канал в настройках.
2. Нажмите **Управлять → Проверить постинг**.
3. Измените текст, при необходимости добавьте файл, проверьте получателя в окне.
4. Нажмите **Опубликовать**. Это настоящая отправка в выбранную социальную сеть.
5. После подтверждения API появится результат и, если площадка его предоставляет, ссылка. TikTok сначала показывает обработку; это ещё не опубликованное видео.

У обычного поста такая же кнопка есть в редакторе. За одно действие выбирается одна площадка. Сохраняется неизменяемая опубликованная копия; исходный черновик остаётся для других площадок. Снимок не редактируется вместе с исходным черновиком. Отправка этого же черновика на ту же площадку второй раз блокируется; для новой публикации создайте новый черновик. Дата в календаре пока не запускает фоновую отправку.

Если площадка отвергла запрос, можно исправить причину и повторить. Если соединение оборвалось после отправки, результат отмечается как неизвестный и автоматического повтора нет: сначала проверьте канал. Это предотвращает дубли при потерянном ответе. Самостоятельное восстановление таких неопределённых записей пока выполняется через канал и новый черновик.

## МАКС

1. Создайте бота в [MAX для бизнеса](https://business.max.ru/) или соответствующем мини-приложении и получите токен в настройках бота. Доступность создания бота определяется правилами платформы и проверкой профиля.
2. Добавьте его администратором в нужный канал или группу с правом отправки сообщений. Введите числовой `chat_id`; `@имя` не заменяет этот идентификатор. Официальные способы получения ID описаны в [MAX API](https://dev.max.ru/docs-api/use-cases/getting-chat-id).
3. Проверка подключения вызывает `/me`, `/chats/{chatId}`, `/chats/{chatId}/members/me`. Отправка при подключении не выполняется.

Текущий официальный адрес — `https://platform-api2.max.ru`, токен передаётся в заголовке `Authorization` без префикса Bearer. Если Node не доверяет цепочке сертификатов этого адреса, добавьте проверенный корневой сертификат, полученный официальным способом, через `NODE_EXTRA_CA_CERTS=/путь/к/сертификату.pem` при запуске сервера. Не отключайте TLS-проверку. Указание на необходимый сертификат опубликовано в [документации MAX](https://dev.max.ru/docs-api/methods/GET/chats/-chatId-/members/me).

Изображение загружается через `/uploads?type=image` в multipart `data`, видео — через `/uploads?type=video`; затем токен вложения передаётся в `/messages?chat_id=...`. MAX WebP в текущем контракте изображений не перечисляет, поэтому здесь принимаются JPEG/PNG. Текст ограничен 4000 символами, загрузка в приложении — 50 МБ. Ссылка появляется только при наличии `message.url` в ответе, обычно для публичного канала. При явном `attachment.not.ready` сервер ждёт обработку и повторяет запрос до пяти раз; сетевые сбои и неопределённые ответы не повторяются. Контракт: [медиа](https://dev.max.ru/docs-api/use-cases/sending-messages/media), [сообщения](https://dev.max.ru/docs-api/methods/POST/messages).

## TikTok

Зарегистрируйте приложение в TikTok for Developers, подключите Login Kit и Content Posting API/Direct Post. Пользователь должен выдать приложению `user.info.basic` и `video.publish`. Вставьте полученный OAuth access token в форму. При необходимости заполните Client key, Client secret и refresh token: сервер обновляет доступ и сохраняет сменившийся refresh token. Секреты не возвращаются браузеру. Подключение проверяет владельца через `user/info` и возможность публикации через `creator_info/query`. [OAuth TikTok](https://developers.tiktok.com/docs/en/oauth-user-access-token-management).

Для непроверенного клиента TikTok ограничивает публикацию режимом `SELF_ONLY` и приватными аккаунтами; публичная публикация требует аудита приложения. Одобрение не гарантируется: Direct Post рассчитан на широкий круг авторов, внутренние инструменты загрузки только для своей команды не подходят для производственного допуска. Локальное подключение не отменяет ограничения TikTok. [Требования к клиентам](https://developers.tiktok.com/docs/en/content-sharing-guidelines).

При открытии окна публикации приложение заново получает имя автора, допустимую видимость, ограничения взаимодействий и максимальную длительность. Видимость пользователь выбирает сам, без предустановленного значения. Комментарии, дуэты и Stitch изначально выключены; настройки, запрещённые аккаунтом, недоступны. Перед отправкой доступны редактирование подписи, указание своего бренда/партнёрства и отметка AI-контента. Длительность файла проверяется по метаданным и лимиту creator info. Требуется явное согласие с [условиями использования музыки](https://www.tiktok.com/legal/page/global/music-usage-confirmation/en), а для платного партнёрства — также с [Branded Content Policy](https://www.tiktok.com/legal/page/global/bc-policy/en). Партнёрство нельзя отправить с приватной видимостью.

Файл с компьютера передаётся как `FILE_UPLOAD`: сервер получает `publish_id` и URL загрузки, отправляет реальные байты видео PUT-запросом с `Content-Range`, а затем проверяет `/post/publish/status/fetch/`. Здесь поддерживается один MP4/WebM до 50 МБ, что укладывается в один допустимый chunk. Изображения и `PULL_FROM_URL` пока не реализованы; для последнего TikTok требует предварительно подтверждённое владение доменом/URL. [Direct Post](https://developers.tiktok.com/docs/en/content-posting-api-reference-direct-post), [передача медиа](https://developers.tiktok.com/docs/en/content-posting-api-media-transfer-guide).

Ответ загрузки не означает публикацию. В приложении сохраняется `processing` и неизменяемый снимок отправленных текста/видео. Только `PUBLISH_COMPLETE` переводит результат в опубликованные. Для приватного видео API может не вернуть публичный ID: подтверждение сохраняется без выдуманной ссылки. Если видео проходит модерацию, публичная ссылка может появиться позже. При `FAILED` отображается причина; при незавершённой отправке можно проверить статус, в том числе после перезапуска сервера. Повторная загрузка одного черновика, пока результат неизвестен или обрабатывается, заблокирована. [Статусы TikTok](https://developers.tiktok.com/docs/en/content-posting-api-reference-get-video-status).

## Хранение и сервер

Маршруты `/api/social/*` работают в `dev`, `preview` и `npm run server`:

- `POST /workspaces` с `{edition}` выдаёт случайные `workspaceId` и `workspaceKey`.
- Остальные запросы требуют `X-Social-Workspace` и `X-Social-Key`.
- `GET /connections`, `POST /connections`, `DELETE /connections/:platform`, `POST /connections/:platform/check` — управление подключениями.
- `POST /publish` с `{postId, platform, title, body, media?, requestId, visibility?, tiktok?}` — ручная отправка. TikTok отвечает `202` и `publication.status: processing`; это не квитанция об опубликованном видео.
- `GET /publications?postId=...` — история и восстановление подтверждений.
- `POST /connections/tiktok/creator-info` — актуальные настройки публикации; ответ `{creator: {nickname, username, privacyLevels, commentDisabled, duetDisabled, stitchDisabled, maxVideoDurationSec}}`.
- `POST /publications/tiktok/:postId/check` — проверка обработки, возвращает `{publication}` со статусом `processing`, `published` или `failed`. `snapshot` содержит отправленные `title`, `body`, `media`; потребитель создаёт опубликованную копию только для `published`.

Объект `tiktok` в ручной отправке: `{privacyLevel, allowComment, allowDuet, allowStitch, commercialContent, brandOrganic, brandedContent, isAigc, consent, durationSec}`. Согласие должно быть явным `true`; настройки проверяются ещё раз по свежему creator info перед отправкой. Для нового окна нельзя автоматически восстанавливать выбранную видимость или согласие прошлой отправки.

Токены площадок зашифрованы AES-256-GCM в `.data/social-connections.json`; ключ — `.data/social-key`, права файлов `0600`. Они не возвращаются API, не попадают в браузерное хранилище или экспорт пространства. В браузере хранится только ключ доступа к локальному пространству, отдельно для аккаунтов LABRIKA. Папка `.data` закрыта для раздачи Vite. Для переноса подключения на другой компьютер нужны оба серверных файла и сохранённый ключ пространства; для удаления подключения используйте кнопку «Отключить».

Запускайте один процесс сервера на одну папку `.data`. Для публичного сервиса нужны серверные пользовательские сессии и роли, защищённые OAuth callbacks и рабочая серверная БД: локальный ключ пространства не заменяет эту инфраструктуру. Публичный запуск не входит в текущие изменения.

## Источники и проверка

Реализовано по официальным контрактам: [Telegram Bot API](https://core.telegram.org/bots/api), [VK API schema](https://github.com/VKCOM/vk-api-schema), [Instagram API with Instagram Login](https://www.postman.com/meta/instagram/folder/6raa77c/instagram-api-with-instagram-login), [Threads API](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api), [YouTube OAuth](https://developers.google.com/youtube/v3/guides/authentication) и [videos.insert](https://developers.google.com/youtube/v3/docs/videos/insert). Видеозагрузки непроверенных проектов YouTube могут ограничиваться приватным доступом независимо от выбранной видимости.

Автотесты используют подменённые ответы API и отдельные временные хранилища. Они проверяют права, сохранение, шифрование, отсутствие утечек, запросы каждой площадки, обработку медиа, изоляцию пространств и повторы. Реальные токены пользователя при разработке не использовались; публикации в настоящих аккаунтах не создавались.
