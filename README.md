# LABRICA

Автономный публичный продукт LABRICA: лендинг, кабинет, админка и собственный backend. Проект не импортирует файлы YGROUP.

## Открыть

```sh
npm install
npm run dev
```

- Лендинг: http://localhost:3000/
- Авторизация: http://auth.localhost:3000/login
- Платформа: http://app.localhost:3000/
- Админка: http://admin.localhost:3000/
- Документы: http://legal.localhost:3000/

В production используются `labrica.pro`, `auth.labrica.pro`, `app.labrica.pro`, `admin.labrica.pro` и `legal.labrica.pro`. Все хосты могут указывать на один процесс `npm run server`: маршрутизатор выбирает нужную точку входа по заголовку `Host`. Для окружений без локальных поддоменов доступны fallback-пути `/auth/login`, `/app`, `/admin` и `/legal`. Старый `/labrika/admin/` удалён и возвращает 404; `/labrika/` перенаправляет в приложение.

## Где вносить изменения

| Версия | Исходники | Точка входа |
|---|---|---|

| Платформа LABRICA | `src/` | `app/index.html` |
| Авторизация | `src/LabrikaEntry.tsx` | `auth/index.html` |

Исходники, сервер, зависимости, окружение и `.data` принадлежат только LABRICA. Публикации, Brand Brain, медиатека, обучение и настройки разделены по аккаунтам. Реестр аккаунтов, тарифов и оформления хранится в `labrika-billing-v1`.

## Публичная главная LABRICA

Лендинг `/` отдаёт полноценный HTML с описанием продукта, заголовками, метаданными Open Graph и структурированным описанием WebApplication. Текст доступен без JavaScript. Кабинет, авторизация и админка помечены `noindex, nofollow`. `noindex` не заменяет контроль доступа.

Вход: `https://auth.labrica.pro/login`, регистрация: `https://auth.labrica.pro/signup`, восстановление пароля: `https://auth.labrica.pro/forgot-password`. Перед регистрацией пользователь отдельно принимает Пользовательское соглашение и согласие на обработку персональных данных; необязательное согласие на новости выключено по умолчанию. Выбор фиксируется локально с версией документа `28.09.2026`. Cookie-баннер отдельно предлагает все cookie, только необходимые или ручную настройку.

Официальные документы доступны на отдельных адресах `https://legal.labrica.pro/<slug>` и как исходные DOCX для скачивания. Публично размещены файлы `01–09` и `11`; технический чек-лист `00_README_BEFORE_PUBLICATION` и инструкция `10_legal_ui_texts` намеренно не копируются в `public` и `dist`. Подвал лендинга ведёт на Пользовательское соглашение, Публичную оферту и Политику обработки персональных данных.

Лендинг следует системной теме через `prefers-color-scheme`, включая карточки, иллюстрации, логотип и модальные окна; настройки темы кабинета на него не влияют. Основной текст доступен без JavaScript; интерактивный чек-лист, анимация маскота, витрина тарифов и диалоги документов требуют JavaScript. Фавикон доступен в SVG, PNG и ICO, отдельная иконка подготовлена для iOS.

Публичный лендинг использует локальную Geometria (Bold для заголовков, Medium для основного текста). Верхний маскот — настоящая 3D-сцена Three.js с прозрачным canvas, без видео, звука и кнопки паузы. Предоставленная статичная модель Meshy подготовлена в Blender: добавлены скелет и анимация, отделены очки, восстановлены скрытые поверхности, глаза и подвижные руки. Персонаж один раз выходит справа, касается очков, опускает их, подмигивает и поднимает указательный палец к верхней кнопке регистрации. Камера неподвижна. Сцена загружается при появлении hero, при уходе за экран и скрытии вкладки приостанавливается, после финального жеста перестаёт перерисовываться. На мобильных DPR ограничен единицей; при `prefers-reduced-motion`, ошибке GLB или отсутствии WebGL показывается статичный прозрачный рендер, без загрузки сцены в режиме reduced motion.

Редактируемый мастер: `assets/mascot/labrica-mascot.blend`; веб-модель: `public/landing-assets/labrica-mascot.glb`; проигрывание: `landing/mascot-scene.ts`. Повторная подготовка: `blender -b --python scripts/prepare-mascot-rig.py -- /полный/путь/к/исходной.glb` (Blender 5.2, `cwebp` для постера). Исходный GLB не изменяется. Прежние WebP-материалы и `scripts/prepare-landing-mascot.mjs` оставлены как архив, hero их больше не использует. Нижний персонаж остаётся отдельной анимацией из предоставленного фотореференса.

Шесть шагов в `landing/Sections.tsx` переключают декоративные макеты из `landing/PlatformMockup.tsx`, а не реальные скриншоты или данные аккаунта. Макеты и AI-диалог не запускают интеграции. Витрина `/#pricing` показывает четыре тарифа по предоставленному референсу; это не платёжная форма и не изменение каталога админки. Реквизиты предпринимателя размещены в HTML подвала. Проверка лендинга на отдельном порту: `LABRICA_TEST_PORT=3016 npm run test:e2e -- tests/smoke.spec.ts`.

Название компании рядом с логотипом появляется после завершения анкеты в Студии. Оно берётся из текущего бренда и обновляется при сохранении настроек; незавершённая анкета не добавляет подпись. Длинное название сокращается в шапке, полное доступно в подсказке.

При сборке с `PUBLIC_SITE_URL` (адрес сайта вида `https://ваш-домен`) добавляются абсолютные canonical и Open Graph URL, создаются `sitemap.xml` с главной страницей и `robots.txt`. Без этой переменной сборка не подставляет выдуманный домен. Локальная страница не индексируется интернет-поиском сама по себе. До публичного запуска также остаются требования к серверной авторизации, хранению команд и финальным документам, описанные ниже.

## Локальный вход без регистрации

Откройте [админку LABRICA](http://admin.localhost:3000/). По умолчанию используются прежние данные: `admin@labrica.com` / `adminadmin`. Форма проверяет их на сервере и создаёт подписанную `HttpOnly`, `SameSite=Strict` сессию на 12 часов; после десяти неудачных попыток действует временная блокировка. Перед публикацией обязательно задайте собственные `ADMIN_LOGIN`, `ADMIN_PASSWORD` и длинный случайный `ADMIN_SESSION_SECRET` в серверном `.env`.

## Что работает локально

- Календарь выбора диапазона на дашборде; светлая, тёмная и системная тема; персональные настройки уведомлений; загрузка аватара.
- Команда в настройках: руководитель, администраторы и отдельные права на приглашения, соцсети, создание, согласование, планирование и сведения о компании. Контакты редактирует руководитель, фото — участник. Приглашения пока работают в том же браузере, где хранится команда; для устройств сотрудников нужна серверная БД и сессии.
- Оплата → сведения плательщика доступны только руководителю и блокируются после сохранения до нажатия «Редактировать».
- AI-чат открывается кнопкой AI рядом с поиском; учитывает сведения компании и историю текущего разговора.
- Обзор, публикации списком или доской, редактор, согласование, календарь с переносом удержанием, аналитика и CSV.
- Студия: идеи, создание и кампании; цель, варианты текста, A/B, адаптация площадок, встроенное медиа и социальный предпросмотр.
- Brand Brain (в Инструментах): компания, продукты/услуги/FAQ/факты/цены, источники, подтверждение сведений, Tone of Voice и запреты. Подтверждённые сведения используются в следующих текстах. Документы сохраняются в IndexedDB; TXT/Markdown/JSON/CSV/HTML можно извлечь локально, остальные форматы сохраняются как файлы.
- Медиатека: загрузка, drag and drop, фильтры, поиск, просмотр, скачивание, удаление. Выбор реальных материалов в студии; готовые файлы от подключённого генератора также попадают в библиотеку. Открывается в Настройки → Пространство.
- Автопилот (в Инструментах): правила, три режима, очередь согласования. Пока пространство открыто, раз в неделю создаёт черновики по темам и подтверждённым фактам. Защита от повторов между вкладками. Внешняя отправка не имитируется.
- События: источники CRM/каталог/RSS/сайт, ручное добавление событий и создание связанных черновиков.
- Конкуренты: до 10 компаний, наблюдения, темы/форматы/реакции/частота, поиск тем, отсутствующих в собственном контенте.
- Кампании: девять связанных материалов вокруг даты запуска, общий прогресс, редактирование отдельных публикаций.
- Repurpose: текст или расшифровка → 10 Threads, 3 Telegram, карусель, 2 сценария Shorts и 3 карточки цитат. Точные и близкие повторы отсекаются. Повторный запуск открывает существующий набор.
- Рейтинг текста: структура, первый абзац, CTA, повторение, визуал, правила бренда. Исправление части замечаний одним действием. Цены и проценты без подтверждённого источника блокируют согласование; запрещённые слова и неподтверждённые специальные утверждения тоже проверяются. Это эвристики, а не полная проверка достоверности.
- LABRICA AI: промо-обзор и отдельный профиль компании с сохранёнными знаниями, источниками, правилами, выборами, правками и фактическими результатами. Предпочтения длины и тона влияют на следующие варианты. Нет выдуманных процентов обученности.
- Регистрация LABRICA: ФИО, телефон, почта и пароль → обязательные согласия → код из письма → обзор. При первом входе в Студию открывается анкета компании по одному вопросу; прогресс сохраняется. SMTP настраивается в админке. Новые сведения требуют подтверждения в Brand Brain. Юридические ссылки открывают соответствующие страницы `legal.labrica.pro`.
- Левое меню плавно поднимается вместе с правой частью до исчезновения заголовка, затем закрепляется; при обратной прокрутке возвращается. Нижние кнопки остаются доступны, полосы прокрутки скрыты. Уведомления показывают достижения по просмотрам, готовность недельного плана и окончание подписки.

BUSINESS выделен как рекомендуемый. Плашка подписки меняется после назначения доступа. Счётчики использования учитывают действия текущего аккаунта за календарный месяц. Оплата реализована визуально: банковские данные не запрашиваются, деньги не списываются, просмотр оформления не активирует подписку. Ручная выдача доступа не прибавляет выручку. Доступ к самой панели защищён серверной сессией, но данные продукта пока остаются локальными для конкретного origin браузера; для единого реестра аккаунтов между `app.labrica.pro` и `admin.labrica.pro` нужна серверная БД. Общего раздела с чужими публикациями нет.

## Согласование без регистрации: технический API

Сервис доступен при `dev`, `preview` и `npm run server`. Элементы выпуска ссылок намеренно не добавлены в рабочий интерфейс.

- `POST /api/approvals` — создать запрос. Обязателен заголовок `X-Approval-Key`. JSON: `{edition, workspaceId, brand, posts: [{id,title,body,platforms}], expiresInMs?}`. Возвращает `id`, случайный `token`, относительный `path`, срок действия.
- `GET /api/approvals/:token` — получить неизменяемое превью материалов без регистрации.
- `POST /api/approvals/:token` — `{action: "approve" | "reject" | "comment", comment?: string}`. Решение финальное; повторное решение возвращает 409.
- `GET /api/approvals/records/:id` — результат для интеграции; нужен ключ выпуска.
- `DELETE /api/approvals/records/:id` — отозвать ссылку; нужен ключ выпуска.

Задайте `APPROVAL_ISSUER_KEY` в окружении сервера. Иначе при первом старте создаётся приватный файл `.data/approval-issuer.key`. Ключ вводится владельцем только в закрытых формах настройки API/SMTP; не встраивайте его в сборку и не публикуйте. Ссылки действуют 7 дней по умолчанию, максимум 30; отозванные и истёкшие возвращают 410. В базе сохраняется SHA-256 токена, а не сам токен. Файлы `.data` исключены из Git. Запросы сохраняют снимок постов; применение ответа к рабочему пространству и доставка ссылок руководителям требуют будущей серверной интеграции.

## Подключения следующего этапа

Сейчас пользовательская часть остаётся локальным приложением. Вход пользователя использует пароль с PBKDF2, но аккаунты и рабочие данные хранятся в браузере: это ещё не серверная аутентификация публичного сервиса. Отдельный вход в админку уже использует серверную подписанную сессию. Перед открытым запуском пользовательской платформы необходимы серверная БД и сессии, разделение организаций, хранение файлов, лимиты и проверка доступа на сервере.

Дообучение весов модели, сканирование сайтов, автоматический сбор конкурентов/CRM/RSS, транскрибация, публикация по расписанию при закрытом приложении и атрибуция регистраций ещё не подключены. Сохранение адреса источника не запускает импорт. Тексты, идеи, планы, кампании, чат и repurpose обращаются к подключённому AI; без подключения успешная генерация не имитируется. Старые генераторы SVG и типографических видео заменены интерфейсом промпта и референсов. Без провайдера изображения и видео не генерируются.

## Подключения соцсетей и публикация

Настройки → Социальные сети: реальные проверки доступа, сохранение ключей на локальном сервере, повторная проверка и отключение. Поддержаны Telegram (бот), VK (сообщество), Instagram и Threads (официальные токены Meta), YouTube (OAuth, в том числе обновление токена), MAX (бот) и TikTok (Direct Post с явным выбором видимости и подтверждением). Для Дзена предусмотрен ручной перенос.

«Проверить постинг» в подключении и «Опубликовать» в редакторе отправляют материал после нажатия пользователя. После подтверждения публикации API создаётся опубликованный снимок со ссылкой; исходный черновик остаётся для других площадок. Повторная отправка на ту же площадку защищена от дублей. Фоновое расписание не запускает реальные отправки автоматически.

Инструкции по доступам, форматы, API и ограничения: [docs/social-connections.md](docs/social-connections.md). Ключи соцсетей зашифрованы в `.data`, не экспортируются и не выдаются браузеру. Реальные внешние публикации при разработке не отправлялись: проверка интеграций выполнена с подменёнными ответами API, а живой тест требует ваших ключей в настройках.

## Генераторы креативов

Изображения: промпт и до 10 референсов. Видео: идея из текущего поста, референсы, 15/30/45/60 секунд, 9:16/1:1/16:9, автоматический режим или проверка сценария. Подготовлены этапы сценарий → кадры → анимация → монтаж, скачивание, добавление к посту и обновление отдельной сцены. При отключённом провайдере показывается ошибка подключения, а введённые параметры остаются в окне.

Серверный адаптер, переменные окружения, контракт пяти этапов и ограничения описаны в [docs/creative-provider.md](docs/creative-provider.md). Ключи остаются на сервере. Реализованы OpenAI для текста и кадров, Higgsfield для анимации и FFmpeg для монтажа. Настройка и ограничения: [docs/ai-providers.md](docs/ai-providers.md). Живые вызовы требуют ключей и доступного баланса сервисов.

## Проверка и сборка

```sh
npm run build
npm run test:e2e
npm run test:server
npm run preview
# Или локальная раздача собранного приложения с API на 3001:
npm run server
```

React 19, TypeScript, Vite, Lucide, Three.js и Playwright. Кабинет и админка используют локальные Onest и JetBrains Mono; лендинг — Geometria и JetBrains Mono. Файлы лицензий и сведения о шрифтах находятся в `public/fonts/`; Geometria предоставлена пользователем и не относится к SIL Open Font License. Есть адаптация под мобильные устройства, управление клавиатурой и reduced motion. Видео в публикациях расходуют localStorage; библиотека файлов использует IndexedDB.

Подключение почты и ограничения подтверждения: [docs/email-confirmation.md](docs/email-confirmation.md). Видимое имя — LABRICA; локальные ключи данных сохранены для совместимости. Основной зелёный цвет LABRICA — `#20DE7C`.
